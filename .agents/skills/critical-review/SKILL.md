# Critical Review

## Objective

Perform a comprehensive review of completed work before it is considered finished.

This skill validates design, code, content, accessibility, responsiveness, performance, and overall quality.

No page, component, or feature should be considered complete until it passes this review.

---

# When to Use

Use this skill after:

- Completing a page.
- Completing a component.
- Completing a feature.
- Before committing significant work.
- Before deployment.

This should always be the final skill executed.

---

# Required Context

Review all relevant documentation together with:

- project-rules.md
- coding-rules.md
- design-rules.md
- content-rules.md

---

# Preconditions

Confirm implementation has already been completed.

Critical Review should never be used during implementation.

---

# Workflow

## Step 1 — Review Business Alignment

Confirm the solution:

- Supports the project vision.
- Aligns with CrestLinks' positioning.
- Solves the intended business problem.

---

## Step 2 — Review User Experience

Evaluate:

- User journey.
- Navigation.
- Information hierarchy.
- Layout.
- Clarity.
- Ease of use.

---

## Step 3 — Review Design

Confirm:

- Visual consistency.
- Layout rhythm.
- Responsive behaviour.
- Component consistency.
- Purposeful interactions.

---

## Step 4 — Review Code

Confirm:

- Clean architecture.
- Reusable components.
- Proper typing.
- Accessibility.
- Performance.
- No unnecessary complexity.

---

## Step 5 — Review Content

Confirm:

- Tone.
- Clarity.
- Accuracy.
- Brand consistency.
- Calls-to-action.
- Grammar and spelling.

---

## Step 6 — Review Technical Quality

Verify:

- SEO.
- Accessibility.
- Performance.
- Broken links.
- Image optimisation.
- Metadata.

---

## Step 7 — Challenge the Solution

Before approving, ask:

- Is this the simplest solution?
- Does this feel premium?
- Would I confidently ship this?
- Is anything unnecessary?
- Can anything be improved without increasing complexity?

Only approve when the answer supports release.

---

# Validation Checklist

Confirm:

✓ Business objectives are satisfied.

✓ User experience is complete.

✓ Design feels premium.

✓ Code is maintainable.

✓ Content builds trust.

✓ Accessibility requirements are met.

✓ Responsive behaviour is complete.

✓ SEO is implemented.

✓ Performance remains strong.

✓ No unnecessary complexity exists.

---

# Common Mistakes

Avoid approving work that:

- Only partially solves the problem.
- Introduces inconsistency.
- Adds unnecessary features.
- Contains duplicated code.
- Feels unfinished.
- Compromises accessibility.
- Relies on assumptions.

---

# Completion Criteria

Work is complete only when:

- Business goals are achieved.
- The buyer journey is fully supported.
- Design, content, and code work together seamlessly.
- The solution is maintainable.
- The implementation reflects the CrestLinks brand.
- The result is production-ready.
