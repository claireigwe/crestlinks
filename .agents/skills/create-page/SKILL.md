# Create Page

## Objective

Design and implement complete website pages that align with the CrestLinks brand, support the user journey, and contribute toward the website's primary goal of generating qualified export enquiries.

Every page should communicate one clear message and guide visitors toward the next logical step in their journey.

Pages should feel cohesive, purposeful, and professionally designed.

---

# When to Use

Use this skill when:

- Creating a new page.
- Rebuilding an existing page.
- Improving page structure.
- Refactoring page layouts.
- Adding new sections.
- Updating page content.

Do not use this skill for individual components.

# Preconditions

Before implementation begins, confirm:

- The page exists within the approved sitemap.
- The page objective is understood.
- The target audience is known.
- The page content exists within content.md.
- Required business information already exists.

Do not invent new content.

# Workflow

## Step 1 — Understand the Page

Identify:

- Why this page exists.
- What business objective it supports.
- What the visitor expects.
- The desired outcome after viewing the page.

Every page should solve a specific problem.

---

## Step 2 — Understand the Story

Treat every page as a narrative.

Determine:

- What visitors should learn first.
- What questions should be answered.
- What confidence should be built.
- Which action should naturally follow.

Avoid treating pages as disconnected sections.

---

## Step 3 — Define the Information Hierarchy

Organise information according to importance.

Visitors should immediately identify:

- Primary message
- Supporting information
- Available actions

Do not compete for attention.

---

## Step 4 — Plan the Layout

Use the approved design direction.

Create visual rhythm by varying layouts while maintaining consistency.

Consider:

- Full-width imagery
- Split layouts
- Cards
- Statistics
- Timelines
- Product showcases
- Call-to-action sections

Avoid repetitive layouts.

---

## Step 4.5 — Challenge the Default Layout

Before implementing the page, ask:

- Is this the most effective layout for the content?
- Does the composition create enough visual interest?
- Can the information be communicated more clearly?
- Does the layout feel premium rather than templated?

Do not default to common landing page patterns if a better composition exists.

---

## Step 5 — Identify Reusable Components

Before creating UI:

Identify:

- Existing components that satisfy the requirement.
- Components that can be extended.
- New reusable components that should be created.

Do not duplicate components.

---

## Step 6 — Build the Page

Implement:

- Responsive layout
- Semantic HTML
- Accessible structure
- Clear visual hierarchy
- Approved content
- Appropriate interactions

The implementation should remain clean and maintainable.

---

## Step 7 — Refine

Review:

- Spacing
- Alignment
- Hierarchy
- Content flow
- Responsive behaviour
- Accessibility
- Performance

Small refinements create premium experiences.

---

# Validation Checklist

Confirm that:

✓ The page supports a clear business objective.

✓ The page follows the buyer journey.

✓ Information hierarchy is clear.

✓ Layout feels balanced.

✓ Components are reusable.

✓ Content follows approved documentation.

✓ Accessibility requirements are met.

✓ Responsive behaviour is complete.

✓ Interactions feel purposeful.

✓ Performance remains strong.

---

# Common Mistakes

Avoid:

- Designing sections independently rather than as one story.
- Repeating identical layouts.
- Creating unnecessary components.
- Inventing content.
- Overusing animations.
- Creating pages with multiple competing messages.
- Ignoring responsive behaviour.
- Breaking established design patterns.

---

# Completion Criteria

A page is complete when:

- It communicates one clear message.
- It supports the buyer journey.
- It aligns with the CrestLinks brand.
- It follows the approved sitemap.
- It uses approved content.
- It feels visually cohesive.
- It performs well.
- It is fully responsive.
- It is accessible.
- It encourages the intended user action.

A completed page should feel like a natural part of the overall website rather than an isolated screen.
