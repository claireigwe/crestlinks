# Project Rules

## Purpose

This document defines the core principles that guide every decision made throughout the CrestLinks website project.

These rules apply to design, development, content creation, and future enhancements.

When multiple solutions are possible, the option that best aligns with these principles should always be chosen.

---

# Project Goal

The objective is to build a premium marketing website that positions CrestLinks as a trusted agricultural export partner for international buyers.

The website exists to:

- Establish credibility.
- Build trust.
- Showcase products and services.
- Generate qualified enquiries.
- Create a premium first impression.

The website is **not** an application.

Avoid introducing application-level complexity unless explicitly required.

---

# Core Principles

## Simplicity First

Always prefer the simplest solution that achieves the desired outcome.

Do not introduce complexity without a measurable benefit.

---

## Business Before Technology

Technology exists to support the business.

Every technical decision should improve the visitor experience or simplify maintenance.

Never introduce technology simply because it is available.

---

## Trust Before Conversion

The website should build confidence before asking visitors to take action.

Every page should reinforce professionalism, transparency, and reliability.

---

## Consistency Over Creativity

Consistency creates trust.

Reusable patterns should always be preferred over unnecessary variation.

Creativity should strengthen usability rather than distract from it.

---

## Quality Over Quantity

Every section should have a clear purpose.

Fewer, well-designed sections are preferable to many shallow ones.

---

## Scalability

The website should support future growth without requiring structural redesign.

Future products, services, and pages should fit naturally into the existing architecture.

---

# Decision Hierarchy

When making decisions, follow this order of priority:

1. Business objectives
2. User experience
3. Accessibility
4. Maintainability
5. Performance
6. Visual refinement

Visual enhancements should never reduce usability.

---

# Scope Control

This project intentionally remains focused.

Avoid adding functionality that is outside the defined scope.

Examples include:

- User authentication
- Admin dashboards
- Shopping carts
- Online payments
- CMS integrations
- Blog functionality
- Inventory systems
- Order tracking

Features should only be added when they directly support an approved business requirement.

---

# Single Source of Truth

Project knowledge is distributed across dedicated documentation.

Never duplicate information unnecessarily.

Use the following documents as authoritative references:

- `vision.md`
- `brand.md`
- `audience.md`
- `company.md`
- `products.md`
- `sitemap.md`
- `content.md`
- `seo.md`
- `design-direction.md`

If information changes, update the appropriate source document instead of creating duplicate content elsewhere.

---

# Reuse Before Creation

Before creating new:

- Components
- Layouts
- Utilities
- Content
- Styles

Always determine whether an existing solution can be reused or extended.

Avoid duplication.

---

# Progressive Disclosure

Do not present all information at once.

Visitors should receive information gradually as they progress through the website.

Each page should answer the questions most relevant to that stage of the buyer journey.

---

# Performance

Performance is a feature.

Prioritise:

- Fast page loads.
- Optimised images.
- Minimal JavaScript.
- Efficient rendering.
- Responsive layouts.

Avoid unnecessary dependencies.

---

# Accessibility

Accessibility is a core requirement.

Every interface should support:

- Keyboard navigation.
- Screen readers.
- Sufficient colour contrast.
- Clear focus states.
- Semantic HTML.

Accessibility should never be treated as an optional enhancement.

---

# Content Integrity

Only publish information that accurately represents CrestLinks.

Never invent:

- Certifications
- Business achievements
- Export capabilities
- Partnerships
- Statistics
- Customer testimonials

Accuracy is more valuable than marketing.

---

# User Experience

Every interaction should reduce friction.

Interfaces should be:

- Predictable
- Clear
- Responsive
- Easy to understand

Users should never have to guess what happens next.

---

# Design Philosophy

The website should feel:

- Premium
- Professional
- Modern
- Calm
- Spacious
- Trustworthy

Design decisions should reinforce confidence rather than visual novelty.

---

# Maintainability

Future developers and designers should be able to understand the project quickly.

Prioritise:

- Clear structure
- Consistent naming
- Modular components
- Reusable layouts
- Logical organisation

Avoid unnecessary abstraction.

---

# Definition of Success

Every completed feature should satisfy the following:

- Solves a real business need.
- Improves the user experience.
- Aligns with the CrestLinks brand.
- Maintains accessibility.
- Performs well.
- Can be maintained easily.
- Does not introduce unnecessary complexity.

Only when all of these conditions are met should a feature be considered complete.

---

# Before Completing Any Task

Verify that the solution:

- Aligns with the project vision.
- Follows the project rules.
- Supports the CrestLinks brand.
- Maintains accessibility.
- Is responsive.
- Is reusable where appropriate.
- Avoids unnecessary complexity.
- Improves the overall user experience.
