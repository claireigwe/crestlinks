# Design Rules

## Purpose

This document defines the design standards for the CrestLinks website.

Every interface should reinforce CrestLinks' position as a premium agricultural export partner through clarity, consistency, and thoughtful user experience.

The objective is not to create a visually complex website, but to create one that international buyers immediately trust.

---

# Design Philosophy

Every design decision should support one or more of the following:

- Trust
- Clarity
- Professionalism
- Simplicity
- Accessibility
- Consistency

Visual decoration should never take priority over usability.

---

# User Experience First

Every interface element should exist for a reason.

Before introducing any visual element, ask:

- Does it improve understanding?
- Does it improve usability?
- Does it support the user's journey?

If the answer is no, remove it.

---

# Visual Hierarchy

Every page should have a clear hierarchy.

Users should immediately identify:

1. Primary message
2. Supporting information
3. Available actions

Hierarchy should be created through:

- Scale
- Position
- Whitespace
- Alignment
- Typography

Never rely solely on colour.

---

# Whitespace

Whitespace is a design element.

Layouts should feel open, calm, and easy to read.

Avoid crowded interfaces.

Give content room to breathe.

---

# Layout

Layouts should feel editorial rather than repetitive.

Avoid stacking identical sections throughout the page.

Instead, create rhythm by alternating layouts while maintaining consistency.

Examples include:

- Full-width imagery
- Split layouts
- Content grids
- Statistics
- Timelines
- Large call-to-actions

Every section should introduce slight variation without disrupting the overall experience.

---

# Grid

Maintain a consistent layout grid throughout the website.

Content should align predictably.

Avoid arbitrary positioning.

Consistency improves trust.

---

# Components

Every component should:

- Solve one problem.
- Be reusable.
- Support accessibility.
- Adapt to different screen sizes.
- Remain visually lightweight.

Components should never become decorative objects.

---

# Cards

Cards should group related information.

Avoid using cards simply because they are visually appealing.

Every card should communicate one idea.

Cards should remain consistent across the project.

---

# Buttons

Buttons should clearly communicate hierarchy.

Primary actions should always receive greater visual emphasis than secondary actions.

Avoid multiple competing primary actions within the same section.

---

# Forms

Forms should minimise effort.

Only request information that is genuinely needed.

Group related fields together.

Provide clear labels and helpful validation.

Reduce friction wherever possible.

---

# Icons

Icons should support understanding.

Do not use icons as decoration.

If removing an icon does not reduce clarity, it should not be included.

---

# Images

Photography should communicate:

- Professionalism
- Quality
- Scale
- Authenticity

Images should never feel generic.

Large imagery should strengthen storytelling rather than simply fill space.

Placeholder imagery may be used during development and replaced later.

---

# Motion

Motion should have purpose.

Animation should:

- Guide attention.
- Reinforce hierarchy.
- Provide feedback.
- Improve perceived responsiveness.

Avoid animation purely for decoration.

---

# Interaction Design

Interactive elements should provide immediate feedback.

Hover, focus, pressed, and active states should feel deliberate and consistent.

Interactions should be subtle rather than dramatic.

---

# Scrolling Experience

Scrolling should feel natural.

Large sections should transition smoothly.

Avoid abrupt visual changes between sections.

The page should feel like one continuous story.

---

# Responsive Design

Design mobile-first.

Every layout should adapt naturally across screen sizes.

Avoid creating desktop experiences that become compromised on smaller devices.

Responsiveness is part of the design process, not a final adjustment.

---

# Accessibility

Every interface should support:

- Keyboard navigation
- Screen readers
- Visible focus states
- Appropriate colour contrast
- Semantic structure

Accessibility should never be sacrificed for aesthetics.

---

# Progressive Disclosure

Do not overwhelm visitors.

Present information gradually.

Each section should answer one question before introducing the next.

Visitors should never feel overloaded with content.

---

# Consistency

Consistency creates trust.

Maintain consistency across:

- Spacing
- Component behaviour
- Interaction patterns
- Layout rhythm
- Content hierarchy

Avoid introducing new patterns when existing ones already solve the problem.

---

# Premium Experience

The interface should feel:

- Calm
- Spacious
- Intentional
- Refined
- Modern
- Professional

Avoid designs that feel:

- Busy
- Generic
- Trend-driven
- Decorative
- Over-animated
- Consumer-focused

---

# Definition of Done

A design is complete when it:

- Clearly communicates its purpose.
- Supports the user's journey.
- Maintains visual consistency.
- Feels premium.
- Is accessible.
- Is responsive.
- Uses reusable patterns.
- Avoids unnecessary complexity.

---

# Before Completing Any Task

Verify that the design:

- Aligns with the project vision.
- Follows the design direction.
- Supports accessibility.
- Uses consistent layouts.
- Maintains clear hierarchy.
- Uses purposeful interactions.
- Feels premium.
- Improves the overall user experience.
